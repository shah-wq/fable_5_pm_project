Chapter 6

Ask SolarFlow

A question box on every staff and dealer screen. It answers from the live database, with the asking person's own permissions, in a few seconds. It is the first AI in the product that people use directly, and the base the later chapters build on.

What people ask it

RoleTypical questions
Admin · PM"Give me the PM report." "Which projects are stuck in Permits, and why?" "What is blocking installs this week?" "Which customers are unhappy right now?" "What is still missing on PRJ-1A2B3C4D?"
Finance"Pipeline value by stage." "Projects completed this quarter and the average days to complete." "Contract value by dealer for projects signed this year."
Sales"Who is quoted but not contacted in 7 days?" "My deal pipeline by stage." "Which of my signed customers are in Survey?"
Dealer"Where are all my projects?" "Which of mine are on hold, and why?" "What is still missing on my projects in Design?"

How it answers

The assistant is Claude Opus 5, given the question and a set of tools. It decides which lookups to run (often several at once), reads the results and writes the answer, with each project's code linked to its page. It runs up to eight rounds of lookups for a hard question. Progress shows while it works ("Building the PM report…").

Chapter 7

Security, cost and limits

Why it cannot leak

Same permissions as the screens

Every tool reads through the asker's own database session, so row-level security decides what comes back. A dealer asking about "all projects" gets their own book. Asking by another dealer's project code returns "no project you can see".

Read-only

No tool writes. Asked to move or change something, it says where in the app to do it. Chapter 15 describes how actions could be added safely.

Offered only what the role has

Sales is not offered the dashboard, and dealers get two tools. Money fields follow the report builder's rules, so a contract value reaches only admin, ops and finance.

Safe on the page

Answers render as formatted text built element by element; no HTML from the model reaches the page. A link is live only if it points inside SolarFlow.

  • Logged: every question is written to the activity log (assistant.asked) with who asked, which tools ran, the time taken and the tokens used. The answers are not stored.
  • Limited: 40 questions per person per hour. Tool results are capped in size, so a runaway query cannot flood the model.
  • Refusals: server-side fallbacks are on. If the model's safety filter declines a request, the API retries it on the model Anthropic recommends for that case, and a final refusal becomes a polite sentence.
  • Conversation: kept in the browser tab only, and sent with each question. Closing the tab forgets it.

Cost

Claude Opus 5 costs $5 per million input tokens and $25 per million output tokens; the fixed instructions are cached at a tenth of that. A typical question runs one or two lookups.

Usage (estimate)Approximate cost
One simple questionAbout 2–5 US cents
A PM report or a multi-step questionAbout 5–15 US cents
20 people × 10 questions a working dayAbout $10–30 a day, $200–600 a month

These are estimates. The activity log records the real tokens for every question, so after a week the actual figure can be read off (a report on assistant.asked). Two settings trade quality for cost: ASSISTANT_EFFORT (default medium; low is faster and cheaper, high is more thorough) and ASSISTANT_MODEL. Test a cheaper model on your own real questions before switching.

Limits today

  • It reads, and does not act.
  • A project list covers the 300 most recent; the report builder has no such limit.
  • It knows what the database knows: a permit status nobody entered cannot be found (chapters 9 and 12 fix that at the source). A long question can take up to 120 seconds on Vercel.
