Chapter 11

Principles and the automation backbone

Cutting human work does not mean trusting a model with everything. It means building a system that does the routine work itself, knows when it is unsure, and puts those cases in front of a person with everything needed to decide in one click.

Seven rules, and the idea behind them

1 · Plain automation first, AI second

If a rule can decide it (a date passed, a file arrived, a status changed), a rule decides it. AI is for reading documents, understanding messages and drafting, where rules cannot reach. Rules are cheaper, faster and never surprising.

2 · The database is the guardrail

Automations act through the same functions and permissions as a person. The stage gate, the hold, the won-deal lock and row-level security refuse an automation exactly as they would refuse a PM. Nothing gets a back door.

3 · Confidence decides who acts

Every AI result carries a confidence score. Above the line, the system acts. Below it, the result goes to the exceptions queue (the table already exists) as a suggestion a person accepts, edits or rejects. The line is set per task, and moves as accuracy is proven.

4 · Evidence, not assertion

A stage advances because a document proves the milestone (the PTO letter with its date) and the fact is recorded with a link to that document. Anyone can see why the system did what it did.

5 · Every action is logged and reversible

Automations write to the same activity log as people, under a named system actor, with the rule or model that acted and its confidence. A wrong move is undone like any other.

6 · Idempotent and retry-safe

Webhooks repeat, jobs rerun and networks fail. Every job can run twice without doing anything twice. The e-signature completion is the pattern to copy.

7 · Measured before it is trusted

Each AI task has a test set of real, labelled examples (fifty bills, fifty permits). A task runs on its own only once it passes on that set, and the set is re-run whenever the model or the prompt changes.

Human on the loop, not in it

People stop being the transport between systems (reading an email and typing it into a form) and become the reviewers of the few cases the system flags. The PM's day starts from the exceptions list, not from the inbox.

Autonomy levels

LevelNameWhat the system does
L0ManualPeople do it; the system records it. (Much of the pipeline today.)
L1AssistedThe system reminds, checks and answers questions. (Stage gates, reminders, Ask SolarFlow.)
L2DraftsThe system prepares the work: fields filled from a document, a reply drafted. A person approves it.
L3Acts, flags doubtThe system acts on high-confidence cases and routes the rest to exceptions.
L4Zero-touchThe system handles the whole step. People see a summary and the rare exception.

Chapter 12

Documents and stage completion

Most of a PM's time goes on moving information from documents into forms. Now that every stage has its attachments (chapter 2), the documents are in one place for a machine to read.

RecommendationHow it works in SolarFlowPeople after
D1Classify every uploadHighSOn document.uploaded, a vision model reads the first pages and labels the file: permit approval, ICA, PTO letter, plan set, utility bill, inspection report, HOA letter, other. A mislabelled or generic upload (a homeowner's "photo") is refiled under the right stage category. A cheap model is enough here.Nobody sorts files. Low-confidence labels go to exceptions.
D2Read the facts into the formHighMPer document type, a structured-output prompt extracts the fields the stage form already has as typed columns: permit number, issue and expiry dates, AHJ; ICA approval date; PTO date; inspection result and date; plan-set system size and module count. Values are written with source = 'ai', the document linked, and a confidence score.The PM reviews only fields below the confidence line, beside the highlighted document.
D3Evidence-based auto-advanceHighSAfter D2 writes a fact, the job re-evaluates the stage (evaluateStage, the same gate people use). If nothing is missing and the evidence is high-confidence, the project advances, with a note naming the document that proved it. Configurable per stage, starting with Inspection & PTO and Permits.The PM stops clicking "advance". They see a feed of what moved and why.
D4Photo quality checkHighMSurvey and install photos are checked against a shot list (roof planes, main panel with the label legible, meter, attic, conduit run, inverter and labels, array complete). A missing or blurry shot is flagged while the crew is still on site, via SMS to the surveyor or installer.No return visits for a missing photo. The PM sees only failures.
D5Missing-document chaserMediumSWhen a stage waits on a document only the homeowner, dealer or utility has (an HOA approval, a bill, the dealer code form), the system uses the existing Ask the customer feature, or emails the dealer, on a schedule: day 0, day 3, day 7, then a task for the PM.The PM steps in only after the third reminder.
D6Expiry and validity watchMediumSDates read by D2 (permit expiry, a lender approval's expiry, the NTP validity) are watched by B1. A warning goes to the PM 14 days before and a task 3 days before, with the project flagged on the board.No expired permits found on install day.
Why this comes first

D1–D3 turn every later integration into a source of documents. A permit portal that cannot be connected can still email a PDF, and once the PDF is read the stage completes itself. It is the widest-reaching change for the effort.
