One homeowner, from the first contact to a system producing power. Each step below is either done by the system on its own, or done by a person with the system checking the work.

6 · DesignPlans, shading report, engineering stamps.
7 · PermitsBuilding permit, ICA, HOA, NTP in parallel tracks; approval letters read into the form; homeowner told at each approval; expiry watched.

Chapter 12

AI integration — what runs today

Two rounds in, the AI does five things: it answers (Ask SolarFlow), it reads documents into the stage forms, it drafts the PM's replies to homeowners, it writes each PM a morning briefing, and — with no model at all — it moves complete projects on. Everything it does carries a confidence, waits for a person when unsure, and is logged. The separate AI & Automation Blueprint describes each in detail (chapters 6–7 and 10) and what comes next.

The rules it runs under

Writes only through the form's allowlist

An accepted or auto-applied value takes exactly the path the stage form's Save takes: known field, valid type, allowed option. A stage move takes the move service's path. There is no back door for the model.

Documents and messages are data

The reading and drafting jobs have no tools that act; they return a schema — values, confidences, evidence, issues — and the application decides under the admin's switches.

A named service account

The automation is a real profile with no password, hidden from every list. Its moves show as its own in the stage history and the activity log, with the tokens each job used.

Cautious defaults

Reading on, auto-apply off, auto-advance for no stage, drafts on, auto-send off, briefings on. The threshold is 0.85. Turn each up once a week of proposals has been accepted mostly unchanged.

Why the platform is well placed for AI

Typed, structured stage data

Every stage field is a real column with a known type, so an AI's answer can be written into a column and validated, not pasted into a notes box.

Rules the AI cannot break

Stage validation, the hold, the won-deal lock and row-level security are all in the database. An AI agent acting through the same API gets exactly the same refusals as a person.

A place for doubt

The exceptions queue gives the AI somewhere to put work it is not sure of, which is what lets it act alone on everything else. It has a screen now, and the document reader fills it.

A full audit trail

Every action is logged with actor and kind, so AI actions can be attributed, reviewed and reversed like anyone else's.
